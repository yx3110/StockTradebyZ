# Wiki Schema — 维护规则

本文件定义 Wiki 的结构约定和操作规则。所有 Claude 会话在操作本 Wiki 时必须遵循这些规则。

## 三层架构

| 层 | 内容 | 权限 |
|---|---|---|
| **Raw Sources** | 代码、配置、git log、数据库 | 只读，不可修改 |
| **Wiki** | `docs/wiki/` 下的 markdown 页面 | Claude 写入 + 用户审核 |
| **Schema** | 本文件，定义规则 | 用户定义，Claude 遵循 |

## 操作闭环

每次代码改动遵循以下流程：

```
Query Wiki → 做改动 → Ingest Wiki → 更新 CLAUDE.md
```

### 1. Query（改动前，必须执行）

开始任何代码改动前：
1. 读取 `docs/wiki/index.md`，了解 Wiki 有哪些页面
2. 根据当前任务关键词，读取最相关的 1-3 个 Wiki 页面
3. 利用获取的上下文：避免重复踩坑、了解历史决策、保持架构一致性

### 2. Ingest（改动后，按需执行）

完成代码改动后：
1. **判断影响范围**：改动是否涉及模型变更、架构调整、新教训、特征变化？
2. **更新已有页面**：如果影响 Wiki 中已有页面，更新相关内容
3. **创建新页面**：如果是全新主题，创建页面 + 更新 `index.md`
4. **追加 log.md**：重大改动在 `log.md` 追加里程碑条目
5. **跳过条件**：纯小 bug fix、代码风格调整、注释修改等不产生噪声

### 3. CLAUDE.md 同步（改动后，按需执行）

改动完成后检查是否需要更新 CLAUDE.md：
- 新命令/入口/配置变更 → 更新 Quick Start / Commands
- 模型版本/性能指标变化 → 更新 ML Systems
- 新文件/目录结构变化 → 更新 Project Structure
- 新教训/陷阱发现 → 更新已知陷阱

### 4. Lint（按需，用户触发）

用户可要求 Claude 审计 Wiki：
- 检查过时信息（与代码/数据库现状不符）
- 发现缺失页面（新组件没有对应文档）
- 检测矛盾内容（页面间数据不一致）
- 识别需要调查的空白领域

## 文件格式约定

### index.md
- 分类目录，每个页面一行
- 格式：`- [标题](相对路径) — 一句话摘要`
- 按主题分组，不超过 50 行

### log.md
- 项目里程碑时间线，只记重大事件
- 格式：`YYYY-MM-DD | 类别 | 描述`
- 类别：`model` / `arch` / `fix` / `feature` / `data` / `eval`
- 新条目追加在文件顶部（最新在前）
- 不记录：纯代码风格修改、小 bug fix、文档格式调整

### 主题页面
- 每页聚焦一个主题
- 用 `[交叉引用](../other/page.md)` 链接相关页面
- 关键数字必须保留（ICIR、V5.2分数、年化收益等）
- 页面内按时间倒序记录变更（最新在前）

## 写入原则

1. **不编造数据** — 所有内容从代码、配置、git log、MEMORY.md 中提取
2. **保留关键数字** — 模型性能指标、评分、日期等精确记录
3. **交叉引用** — 页面间互相链接，形成知识网络
4. **混合语言** — 技术术语英文，解释和决策记录中文
5. **聚焦主题** — 每页一个主题，避免内容膨胀

## 与 Memory 系统的分工

| 维度 | Memory (.claude/memory/) | Wiki (docs/wiki/) |
|---|---|---|
| 范围 | 对话级上下文、用户偏好 | 项目级知识、架构决策 |
| 生命周期 | 短~中期，可能过时 | 长期，主动维护 |
| 维护者 | Claude 自动写入 | Claude 写入 + 用户审核 |
| 粒度 | 细节、偏好、当前状态 | 总结、决策、演化历程 |
| 示例 | "用户偏好中文commit" | "V4.6重训练失败因为小盘加权×2.5" |
