# NG v1.2.4 Design Spec: Conservative Increment over ng1.0.1

**Date**: 2026-04-16
**Status**: REJECTED (2026-04-17, Stage 3.5 V5.2=48.5% B)
**Base**: ng1.0.1 (production, V5.2=72.1% A+, Sharpe=2.753, MaxDD=-11.7%, ~~Pre-2020=73.7%~~ 注: Pre-2020=45.5% B 实测, 2026-04-20 订正 ghost number)
**Branch lineage**: ng1.0.1 → ng1.2.x → **ng1.2.4** (post-ng1.2.3 conservative pivot)
**Goal**: V5.2 ≥ 73% A+, Pre-2020 ≥ 70%, MaxDD ≤ -12%, all simultaneously, with HIGH confidence

---

## 1. Problem Statement (Recap from ng1.2.3 Postmortem)

ng1.2.3 added 12 moneyflow + 6 mined factors + downside label penalty. Fast-check 三阶段全 PASS, training WF ICIR=1.26 (+35% vs ng1.0.1 0.93), 但 production 评估双崩:

| 指标 | ng1.0.1 | ng1.2.3 WF-OOS | ng1.2.3 Pre-2020 |
|---|---|---|---|
| V5.2 | 72.1% A+ | **45%** | **31%** |
| 年化 | +165.7% | -8.8% | -63.3% |

**Root cause** (per `docs/wiki/architecture/ng123_postmortem.md`):
1. λ=0.6 downside penalty 把多数涨股 label 翻号
2. Mined + Moneyflow 全部 contrarian, 累积反向偏差
3. Stage 3 用 WF training ICIR 选 λ, OOS 反向
4. fast-check methodology gap: training ICIR ≠ production score

## 2. Design Philosophy: Minimum Viable Increment

ng1.0.1 已经 V5.2=72.1% A+, **进一步突破的概率 < 50%**, 失败 (≤72%) 的概率 ≥ 50%. ng1.2.4 必须最大化"加 1 个 small fix 不破坏现有 alpha"的概率.

**核心原则**: 改动越少, 失败 surface 越小. ng1.2.3 改 3 轴失败, ng1.2.4 只改 1 轴 (加 2 个最强 factors).

## 3. Three-Axis Decisions

| 轴 | ng1.2.3 | ng1.2.4 | Rationale |
|---|---|---|---|
| **特征空间** | -12 弱 + 12 mf + 6 mined | **+2 mf only** | top 2 P90 单独验证更可控 |
| **因子来源** | mf + mined | **mf only (top 2)** | mined 已证累积反向 |
| **Label** | excess - 0.6×downside | **excess only** | downside penalty 过重, 已证翻号 |

## 4. Factor Selection — The 2 Chosen mf Factors

From Stage 1 (`reports/ng123/fastcheck/stage1_recalibrated.json`):

1. **`mf_net_elg_20d_ratio`** — |IC|=0.023, |ICIR|=**0.524** (ng101 P90 percentile)
2. **`cs_rank_mf_net_elg_20d`** — |IC|=0.023, |ICIR|=**0.511** (ng101 P90 percentile)

These are the only two mf factors with `|ICIR| > 0.5` (ng101 P90 bar). All other 4 accepted in ng1.2.3 (5d ratios, smart_net_share) had P75-level signal — useful but not robust enough to add when alpha headroom is tiny.

Both are based on `net_elg` (super-large order net flow over 20-day window). One is raw ratio, one is industry-rank-percentile. They measure the same underlying signal at different cross-sectional aggregations.

**Risk**: Even these 2 are contrarian (negative IC). However, ng1.0.1 internally already has many contrarian factors (`pullback_*`, `volume_contraction`, `n_sectors_strong` etc) without breaking — so 2 more should be tolerable.

## 5. Architecture

```
ng1.0.1 baseline (64 stock + 10 market = 74 features)
                 │
                 ├──────  +  2 mf factors  =  76 stock + 10 market
                 │            (mf_net_elg_20d_ratio, cs_rank_mf_net_elg_20d)
                 │
                 ├──────  Label  =  industry_excess_kd  (UNCHANGED, no downside penalty)
                 │
                 ├──────  Training  =  3-seed ensemble (UNCHANGED)
                 │
                 └──────  NEW: Stage 3.5 production spot check (90-day backtest V5 ≥ 60%)
```

## 6. Branching strategy

ng1.2.4 reuses ng1.2.x branch logic from ng_schema.py:
- `VERSION_TABLE_MAP['ng1.2.4'] = 'ng124_feature_cache'`
- `SCHEMA_VERSION_MAP['ng1.2.4'] = 'ng1.2.4'` (own schema, like ng1.2.3 was — but with fewer columns)
- `_schema_sql` extension: NO downside_kd columns (no penalty), only base + 2 new mf factor names auto-included via features_json
- ng1.2.4 INHERITS the `not is_12` guards already in place for ng1.0.4/ng1.0.7

## 7. Stage 3.5 Production Spot Check (NEW Gate)

The critical addition that ng1.2.3 lacked. Between Stage 3 (training) and Phase 2 (full backfill+training), add:

**Stage 3.5: 90-day production simulation**
1. Train minimal model on 2020-01 → 2024-09 (ng1.2.4 with 2 mf factors)
2. Generate 90 daily reports for 2024-10 → 2025-01 (3-month spot check)
3. Run `run_north_star_eval.py --backtest --report-dir ... --top-n 10 --focus-days 10`
4. **Pass criterion**: V5.2 estimated score ≥ 60% (relaxed from 73% production gate; this is just sanity check)
5. **Fail action**: Abort, write postmortem, do NOT proceed to full backfill+train

This gate would have caught ng1.2.3's failure with ~1h investment (vs 8+ hours wasted on full pipeline).

## 8. Acceptance Criteria

ALL must hold for promotion to production:

| Metric | Threshold | ng1.0.1 baseline | Reasoning |
|---|---|---|---|
| WF-OOS V5.2 | **≥ 73% A+** | 72.1% | Strictly beat baseline |
| WF-OOS 10d ICIR | ≥ 0.85 | 0.93 | Allow up to 9% ICIR decay |
| WF-OOS Sharpe | ≥ 2.5 | 2.753 | Allow 9% Sharpe trade |
| WF-OOS MaxDD | ≤ -12% | -11.7% | At parity (no improvement required, just don't worsen) |
| Pre-2020 V5.2 | ~~≥ 70% A+~~ 已作废 | ~~73.7%~~ 45.5% B | **2026-04-20 订正**: 原 baseline 是 4-10 评估 bug 遗留 ghost number; 真实 baseline 45.5% B, 后续 gate 改为 "净年化 ≥ 0% + 超额胜率 ≥ 60%" 同向 alpha 验证 |
| Annualized return | ≥ 130% | 165.7% | Allow 21% return trade |

If V5.2 lift < 1pp (e.g. 72.5%), still accept if Pre-2020 净年化 ≥ 0% (cross-regime stability win, not A+ gate).

## 9. Risk Matrix

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| 2 mf factors still contrarian → reverse signal | **Medium** | Critical | Stage 3.5 catches before full backfill |
| ng1.0.1 features dropped via filter accidentally | Low | Critical | NO drop — ng1.2.4 keeps all 64 ng1.0.1 stock features |
| Cache build fails midway | Low | Low | INSERT OR REPLACE idempotent |
| Stage 3.5 false positive (60% threshold too low) | Medium | Medium | Aim for ≥65% to leave margin |
| Time wasted if rejected | Low | Low | Stage 3.5 limits waste to ~3-4h |

## 11. Open Questions for Review

1. **Should we add a 3rd factor (mf_smart_net_share_20d, P75) if Stage 3.5 spot check shows neutral?**
   - Recommendation: No. Keep variant scope tight; if 2 work, freeze.

2. **Should we test λ=0.0 (no penalty) vs λ=0.15 (very mild) at Stage 3.5?**
   - Recommendation: No. Stage 3.5 should only validate the 2-factor addition. λ=0 is the spec.

3. **Should we drop 2-12 weak features from ng1.0.1 to avoid feature bloat?**
   - Recommendation: No. ng1.0.1 dropped 12 already (in ng1.1.0/ng1.2.3); ng1.2.4 stays close to production baseline.

4. **Are 2 factors enough to move V5.2 by 1pp?**
   - Honest answer: Maybe not. But the goal is to **not break ng1.0.1** while testing whether mf signal works. If Stage 3.5 shows V5≥65%, we're at parity, which is success given our prior failure.
