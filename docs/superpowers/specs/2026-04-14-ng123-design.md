## 1. Problem Statement

ng1.2.0 / ng1.2.1 / ng1.2.2 (margin loss / vol-norm rank / quintile CE) all failed against ng1.0.1 baseline:

| Variant | WF-OOS V5.2 | Pre-2020 V5.2 | Root cause |
|---|---|---|---|
| ng1.2.0 (margin) | C 41.8% | C ~32% | hinge loss zeros out most pairs in A-share noise |
| ng1.2.1 (vol-norm) | C ~40% | D ~27% | rank transform destroys IC ceiling |
| ng1.2.2 (quint-CE) | C 41.8% | C 37.2% | tail class too sparse, short-horizon labels unstable |

**Common root cause**: all three changed loss/label only, kept ng1.0.1's identical 64-feature signal space → no new information ⇒ no possible alpha gain. Empirically validated MEMORY.md insight:
> "三者都改 loss/label 而没改特征，等于在同一信号空间下变着花样输"

ng1.2.3 must change **all three axes simultaneously** (factor formulas, feature space membership, label form) but each change must be *principled and risk-bounded*, not speculative.

## 4. Factor Specifications

### 4.1 Moneyflow factors (12 new)

**Theory**: Tushare moneyflow_daily classifies orders by size:
- Super-large (`elg`): ≥ 1M ¥ → institutional / hot money
- Large (`lg`): 200K – 1M ¥ → big retail / small institution
- Medium (`md`): 40K – 200K ¥ → medium retail
- Small (`sm`): ≤ 40K ¥ → retail

Hypothesis (with academic + empirical support):
1. Net institutional flow (`net_elg`) leads price short-to-medium term
2. Smart-vs-retail divergence is a contrarian indicator (smart in + retail out = bullish)
3. Persistence of net flow > single-day magnitude
4. Industry-relative flow rank > absolute (same logic as ng1.0.1's cs_rank suite)

**Group A: Smart Money Net Flow Magnitude (4 factors)**

| # | Name | Formula | Range |
|---|---|---|---|
| 1 | `mf_net_elg_5d_ratio` | `Σ(buy_elg-sell_elg, 5d) / Σ(buy_total+sell_total, 5d)` | [-1, 1] |
| 2 | `mf_net_elg_20d_ratio` | `Σ(buy_elg-sell_elg, 20d) / Σ(buy_total+sell_total, 20d)` | [-1, 1] |
| 3 | `mf_net_lg_5d_ratio` | `Σ(buy_lg-sell_lg, 5d) / Σ(buy_total+sell_total, 5d)` | [-1, 1] |
| 4 | `mf_smart_net_share_20d` | `Σ(net_elg+net_lg, 20d) / Σ(\|net_elg\|+\|net_lg\|+\|net_md\|+\|net_sm\|, 20d)` | [-1, 1] |

**Group B: Persistence (2 factors)**

| # | Name | Formula | Range |
|---|---|---|---|
| 5 | `mf_elg_persistence_20d` | `Σ(sign(net_elg_daily), 20d) / 20` | [-1, 1] |
| 6 | `mf_smart_consistency_5d` | `Σ(1[sign(net_elg_daily)=sign(net_lg_daily)], 5d) / 5` | [0, 1] |

**Group C: Divergence + Acceleration (2 factors)**

| # | Name | Formula | Range |
|---|---|---|---|
| 7 | `mf_smart_retail_divergence_5d` | `sign(Σ(net_elg, 5d)) - sign(Σ(net_sm, 5d))` | {-2, 0, +2} |
| 8 | `mf_elg_acceleration_5_20` | `mf_net_elg_5d_ratio - mf_net_elg_20d_ratio` | ≈ [-1, 1] |

**Group D: Cross-Sectional Industry Ranks (4 factors)**

| # | Name | Computed via |
|---|---|---|
| 9 | `cs_rank_mf_net_elg_5d` | `_industry_percentile_rank(#1, peer_values)` |

| 11 | `cs_rank_mf_smart_net_share_20d` | `_industry_percentile_rank(#4, peer_values)` |

### 4.2 Mined factors (6 new)

**Selection protocol** (do NOT pre-fix the 6 names — let data decide):

```bash
python3 scripts/factor_mining_pipeline.py \
  --start-date 2022-01-01 \
  --end-date 2026-04-14 \
  --depth 2 \
  --n-stocks 800 \
  --min-icir 0.5 \
  --min-ic 0.04 \
  --max-corr 0.5
```

**Secondary filters** (applied to mining output before final selection):
1. **Orthogonality**: Pearson \|corr\| < 0.5 vs all 64 ng101 features AND all 12 new moneyflow factors
2. **Sign flip**: If IC < 0, multiply factor value by -1 (record `sign_flip=True` in spec)
3. **Economic interpretability**: Reject pure black-box compositions (e.g., `op_inv(ts_skew(volume,60))`); require one-sentence semantic description
4. **Cross-regime stability**: Compute IC separately on 2022 (bear) and 2024 (recovery), require same sign AND \|IC\| > 0.02 in BOTH

After all filters, take **top 6 by ICIR**. Output spec file `ml_models/ng/ng123_mined_factors.py` with:


## 5. Label Specification

### 5.1 Formula

For each horizon k ∈ {3, 5, 10, 15}:

```python
# Forward path data (look-ahead, used ONLY for label computation, never inference)
future_closes_kd = [close[t+1], close[t+2], ..., close[t+k]]
path_min_kd      = min(future_closes_kd) / close[t] - 1     # ≤ 0 typically
downside_kd      = max(0, -path_min_kd)                      # ≥ 0

# Industry excess (existing in ng1.0.1)
forward_return_kd  = close[t+k] / close[t] - 1
industry_mean_kd   = mean(forward_return_kd over peers in same industry on date t)
excess_kd          = forward_return_kd - industry_mean_kd

# NEW: soft downside-penalized label
ng123_label_kd     = excess_kd - LAMBDA * downside_kd
```

with `LAMBDA = 0.3` (default; subject to ablation in Section 6.3).

### 5.2 Why λ = 0.3

Empirical magnitudes in ng1.0.1 training data:

| Quantity | Typical magnitude |
|---|---|
| `excess_10d` cross-section std | 0.06 – 0.10 |
| `downside_10d` median (healthy winners) | 0.02 – 0.05 |
| `downside_10d` (pathological volatility) | 0.10 – 0.20 |

Effect on representative cases at λ=0.3:

| Stock pattern | excess | downside | ng1.0.1 label | ng1.2.3 label | Effect |
|---|---|---|---|---|---|
| Clean winner | +0.05 | 0.03 | +0.05 | +0.041 | Mild rank reduction |
| Volatile winner | +0.05 | 0.15 | +0.05 | +0.005 | Strong demotion (intended) |
| Volatile loser | -0.05 | 0.20 | -0.05 | -0.110 | Extra penalty |
| Clean loser | -0.05 | 0.05 | -0.05 | -0.065 | Mild penalty |

**Comparison vs ng1.0.4 failure (λ=1.5)**:
- At λ=1.5, a clean winner with `excess=+0.05, downside=0.05` becomes label `-0.025` — **rank order flipped**, label sign changed
- Over-penalization at this scale destroyed ng1.0.4's predictive signal (Sharpe up but MaxDD blew to -32.6%)
- λ=0.3 is precisely 1/5 of ng1.0.4's penalty — keeps rank order intact for typical winners

### 5.3 λ ablation in fast-check

5 candidates × 2 WF windows = 10 mini-trainings (~2 min each, total ~30 min):

| λ | Interpretation | Expected outcome |
|---|---|---|
| 0.00 | Pure ng1.0.1 label (sanity) | Confirms whether feature changes alone help |
| 0.15 | Very mild | Transition step |
| **0.30** | **Default — recommended** | Expected 10d ICIR ≥ 0.95 × baseline, MaxDD improves |
| 0.45 | Moderate | Expected MaxDD further improves, ICIR starts decay |
| 0.60 | Stronger (still 0.4× of ng1.0.4's) | Upper bound — expected ICIR clearly degrades |

**Selection rule**: pick the **largest λ that retains ≥ 0.95 × baseline 10d ICIR**. This maximizes risk control without destroying predictive signal.

### 5.4 Multi-horizon consistency

All 4 horizons (3d/5d/10d/15d) use the **same λ**. Reason: LightGBM multi-target shares feature representation; per-horizon λ would create conflicting gradients across heads.

ICIR-weighted aggregation across horizons is unchanged (existing ng1.0.1 logic).

## 6. Fast-Check Protocol (Three-Stage Gate)

Total budget: ~6 hours = 1 working day. Output: Go/No-Go decision document.

### 6.1 Stage 1 — Moneyflow factor IC validation (~4 hours)

**Steps**:
1. Compute 12 moneyflow factors on full A-share universe × 2022-01 → 2026-04
   - No need for full historical backfill at this stage; sample sufficient
2. Compute cross-sectional IC vs `label_10d_excess` (use ng1.0.1's existing label — this stage asks "do factors predict?", not "does new label work?")
3. Compute correlation matrix vs all 64 ng101 features

**Pass criteria** (ALL must hold):
- [ ] ≥ 6 factors with \|IC\| > 0.02 AND \|ICIR\| > 0.3
- [ ] ≥ 4 factors with \|IC\| > 0.04 AND \|ICIR\| > 0.5
- [ ] ≥ 8 factors with \|corr\| < 0.5 vs all ng101 features
- [ ] At least 2 of the 4 cs_rank factors pass (validates industry-rank transformation)

**Fail action**:
- If < 6 pass → moneyflow concept fails; abort entire moneyflow group; project terminated
- If 6–11 pass → keep only passing factors for Stage 4
- Document failed factors and reasons in `reports/ng123/fastcheck/stage1_moneyflow_ic.csv`

### 6.2 Stage 2 — Mined factor re-validation (~1 hour)

**Steps**:
1. Re-run `factor_mining_pipeline.py` with stricter parameters (per Section 4.2)
2. Apply orthogonality filter vs ng101 + already-passed moneyflow factors
3. Cross-regime stability check: IC on 2022 (bear) and 2024 (recovery) separately

**Pass criteria**:
- [ ] ≥ 6 mined factors satisfy: \|ICIR\| > 0.5 AND orthogonal AND cross-regime stable

**Fail action**:
- If < 6 pass → drop mined factor group entirely; ng1.2.3 uses 12 moneyflow + 0 mined (keeps total 64 features after dropping 12 ng1.0.1 features)
- If 6+ pass → take top 6 by ICIR

### 6.3 Stage 3 — Label λ sensitivity (~30 minutes)

**Steps**:
1. Use feature set passing Stages 1+2 to train 5 λ × 2 WF windows = 10 mini-models
2. Per mini-model: `start_date=2022, leaves=15, n_windows=2, save_model=False`
3. Compare 10d ICIR(label_10d_excess) — common yardstick across all λ (use unpenalized excess label as evaluation target, avoiding circular comparison)

**Pass criteria**:
- [ ] Best λ achieves ≥ 0.95 × ng1.0.1 baseline 10d ICIR
- [ ] Best λ is NOT 0.0 (if 0.0 wins, label change provides no value — proceed with λ=0)

**Fail action**:
- If all λ > 0 degrade > 5% → label transform fails; train ng1.2.3 with **λ=0** (still ng1.2.3 named; only feature changes count)
- If λ=0.6 wins → flag for future research (downside signal stronger than expected)

### 6.4 Stage 4 — Combined Go/No-Go gate

**Go conditions** (any one suffices):
- A. Stages 1+2 pass → 12 mf + 6 mined + selected λ → full training (70 stock features = 64 - 12 + 12 + 6)
- B. Stage 1 passes, Stage 2 fails → 12 mf only + selected λ → full training (64 stock features = 64 - 12 + 12, but composition changed)
- C. Stages 1+3 fail → project terminated; write postmortem

**Output**: `reports/ng123/fastcheck/decision.md` with:
- Pass/fail per stage
- Final feature roster
- Selected λ
- Estimated training time
- Go/No-Go recommendation

## 12. Open Questions for Review

1. **Should λ ablation include negative values (e.g., λ=-0.1, "downside-bonus")?**
   - Recommendation: No. Negative λ would reward drawdowns, theoretically nonsensical.
2. **Should we also test downside_pct (relative to industry mean drawdown) vs raw downside?**
   - Recommendation: Defer to ng1.2.4 if ng1.2.3 succeeds. One change per iteration.
3. **Should mined factor count be capped at 6, or accept up to 10 if more pass filters?**
   - Recommendation: Hard cap at 6 to prevent feature bloat (ng1.1.0 lesson: more ≠ better).
4. **Should we drop ng1.1.0 P2 factors (peg_proxy, pb_roe_ratio) from feature space?**
   - Recommendation: Yes — already in the 12-drop list per ng111 audit.
